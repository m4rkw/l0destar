# ISO-9141 Loopback Test

**Before building, installing or relying on any of this, read the [project disclaimer](../DISCLAIMER.md).**

Verifies the K-line and L-line interface on v2.5K/v2.6K boards using the
L9637D transceiver's bus loopback (TX drives the K-line, same chip's RX
reads it back). No external equipment needed.

On bench setups with two L9637D transceivers, the test instead streams
bytes K1->K2 and K2->K1 across the wire.

## Hardware

- l0destar v2.6K board (L9637D transceiver + TXS0104E level shifter)
- 12V bench supply (powers the K_EN domain via P0.23)
- No external adapter or loopback plug required - the L9637D echoes its
  own transmissions on the shared K-line

## What the test covers

1. **K static loopback** - drives TX dominant/recessive and verifies RX
   follows through the L9637D
2. **K byte stream** - transmits all 256 byte values (0x00-0xFF) at the
   10.4 kbaud K-line bit rate and checks each echoes back intact
3. **L-line toggle** (if L_SEND/L_RECV pins are fitted) - asserts the
   L pulldown FET and verifies L_RECV follows

## Running the test

1. Enable in `local.conf`:
   ```
   CONFIG_APP_BOARD_L0DESTAR_V2_6_KLINE=y
   CONFIG_APP_KLINE_TEST=y
   ```

2. Build and flash:
   ```
   ./build.sh && ./flash.sh
   ```

3. Reset the board. Serial output shows:
   ```
   *** ISO-9141 TEST ***
   K1 static: idle=1 TX=0->RX=0 TX=1->RX=1 OK
   K1 loopback: TX=P0.0 RX=P0.1
   K1 loop: 256/256 bytes OK
   L-line: idle=1 send=1->0 send=0->1 OK
   PASS: ISO-9141 test
   *** ISO-9141 TEST DONE ***
   K-line test complete - halting.
   ```

4. Comment out `CONFIG_APP_KLINE_TEST=y` when done.

## Troubleshooting

**K1 static FAIL (TX=0 -> RX=1)** - RX doesn't follow TX through the
L9637D. Check:
- K_EN domain is up (serial should show "K domain on")
- AUX domain is up (powers the TXS0104E VCCA)
- Correct board variant selected (`V2_6_KLINE`, not `V2_6_CAN`)
- L9637D is populated and has 12V on its Vs pin

**Byte mismatches** - bit-timing drift. The K-line bit rate is 10.4 kbaud
(96 us/bit), bit-banged with `k_busy_wait`. Check that no high-priority
interrupts are starving the bit-bang loop.

## Signal path (v2.6K)

```
nRF P0.0 (K1_TX) --> TXS0104E A2/B2 --> L9637D TxD --> K-line
                                                          |
nRF P0.1 (K1_RX) <-- TXS0104E A1/B1 <-- L9637D RxD <----+
```

Both AUX (TXS0104E VCCA) and K (L9637D Vs, TXS0104E VCCB) domains must
be powered for the signal path to work.
